# DCM 연동 현황 대시보드 — 업체용

업체별 로그인으로 대웅제약 마스터 현황과 조치 내용을 조회하고, 업체 의견을 별도로 작성하는 GitHub Pages 대시보드입니다. 인증·조회·저장은 기존 Google Apps Script와 Google Sheet를 사용합니다.

## 사용 방법

1. 업체명과 기존 접속코드로 로그인합니다.
2. 월·업체/권역을 선택하여 연동률, 연동 필요처, 공급처와 전월 변동을 확인합니다.
3. KPI 카드를 클릭하거나 통합 Action Board의 보기·세부 조건·검색을 사용합니다. 보기는 **전체 거래처 / 우선 조치 필요처**, 세부 조건은 기존 7개를 유지합니다.
4. 파란색 마스터 입력을 참고하여 초록색 업체 입력을 작성합니다. 입력은 먼저 이 브라우저에 보관됩니다.
5. **저장(마스터에게 전달)**을 누르면 최대 40개 필드씩 전송합니다. 확인된 항목만 미전송 목록에서 제거합니다. 오류가 나면 내용을 확인한 뒤 같은 버튼으로 다시 전송할 수 있습니다.
6. 필요한 경우 별도 SRM 협의 이력을 작성하고, 선택한 Action 목록을 Excel로 다운로드합니다.

## 현황과 저장 상태를 읽는 방법

- **최근 조회 현황 / 최신 확인 중**: 1시간 이내 브라우저 조회값 또는 마스터 보관값을 표시하면서 현재 자료인지 확인하는 중입니다.
- **마스터 현황 / 최신 확인**: 정상 조회 또는 로그인 응답의 현재 데이터 버전과 일치함을 확인했습니다. 화면에 확인 시각을 표시하며, 응답에 원본 갱신 시각이 있으면 함께 표시합니다.
- **최신 현황 확인 실패**: 이전 조회값을 유지합니다. 성공으로 표시하거나 오류 응답으로 표를 비우지 않습니다. 새로고침으로 다시 확인할 수 있습니다.
- **미전송**: 브라우저에 있는 업체 입력입니다. 서버 저장 완료와 구분하며, 명시적으로 저장 버튼을 눌러야 전송합니다.
- **저장 완료**: 서버가 제출한 거래처·필드·값을 모두 일치하게 확인한 항목입니다. 중복되거나 누락된 확인 응답은 성공으로 처리하지 않습니다.

상태 문구는 접근성 알림 영역으로 제공됩니다. 마스터/업체 입력 구분, KPI 산식, 진행중·완료 표시와 기존 필터는 유지합니다.

## 계산 기준

- 전체 연동률 = O / (O + X)
- 평가건수는 대웅제약·대웅바이오·한올바이오의 O/X를 법인별 각각 집계합니다.
- 연동 필요 절대처수는 업체/권역과 실사업자번호 기준으로 중복을 제거합니다.
- 공급 절대처수는 세 법인 중 하나라도 O/X가 있는 거래처를 같은 기준으로 한 번 집계합니다.
- 신규 공급은 전월 전체 미공급 → 당월 하나라도 O/X, 공급 중단은 그 반대입니다.
- 신규 공급처수 − 공급 중단처수 = 공급 절대처수 증감입니다.
- 동일 실사업자번호가 다른 도매업체에 있으면 각 업체에서 각각 1처로 계산합니다.
- X 평가건수와 표의 고유 거래처 수는 단위가 달라 일치하지 않을 수 있습니다.
- SRM 진행중·완료 집계는 같은 월·업체의 Action Board 표시 상태와 같은 기준을 사용합니다.

## 2026-10-21 조회·저장 신뢰성 개선

- 로그인·로그아웃마다 진행 중 요청을 취소하고 접속 세대를 분리합니다. 이전 접속의 늦은 로그인, 조회, 저장 응답은 새 접속의 자료나 입력에 반영되지 않습니다.
- 기존 인증·상태 조회 9초, 데이터 조회·저장 18초 제한을 유지합니다. 같은 조회·저장 동작의 중복 실행을 막습니다.
- 정상적인 빈 배열은 빈 결과로 받아들이고, 필수 구조가 없는 현황·조치·협의 응답은 이전 정상 자료를 보존한 채 오류로 표시합니다.
- 저장을 시작하기 전에 요청한 조치 조회가 늦게 도착해도 이후 확인된 저장값을 덮어쓰지 않습니다. 저장 중 추가로 수정한 필드도 남겨 둡니다.
- SRM 저장은 현재 API의 `saved: true`와 일치하는 `requestId`를 확인합니다. 같은 작성 내용의 재시도는 같은 ID를 사용하고, 내용이 달라지면 새 ID를 사용합니다. 성공해도 다른 거래처나 이후 수정한 작성 내용은 지우지 않습니다.
- 별도 협의 이력 조회가 실패하면 마지막 정상 조회 이력을 유지하고 실패 상태를 표시합니다. 로그아웃 시 이전 업체의 협의 이력은 제거합니다.
- 유효한 마스터 보관값이 있으면 기존 로그인 응답으로 인증·KPI·조치 자료를 함께 처리하는 빠른 경로를 유지합니다. 새 라이브러리나 추가 부트스트랩 요청은 도입하지 않았습니다. Excel 라이브러리는 다운로드할 때 불러옵니다.
- Apps Script 주소·접속코드 방식·서버 API·데이터 스키마는 변경하지 않았습니다.

## 브라우저 보관과 서버 저장

현재 탭의 최근 조회 자료는 `sessionStorage`, 아직 보내지 않은 업체 입력과 SRM 작성 내용은 업체별 키의 `localStorage`에 보관합니다. 미전송 입력 초기화는 서버에 확인된 업체 입력이나 마스터 입력을 삭제하지 않습니다. 로그아웃 시 화면과 진행 중 요청을 정리하며, 미전송 작성 내용은 재접속 후 사용할 수 있도록 유지합니다.

## 검증

```sh
node tests/harness.mjs
```

추가한 `tests/partner-reliability-regression.mjs`는 지연 응답과 실패 응답을 실제 비동기 흐름으로 주입하여 접속 전환, 요청 취소·제한시간, 잘못된 스냅샷, 캐시 상태, 중복 저장 확인, 저장 중 수정, SRM 작성 내용 보존을 검증합니다. 기존 월별 이력, KPI·필터, 마스터/업체 필드, SRM 표시 일치 회귀 검증도 함께 실행합니다.

브라우저용 스크립트 문법은 Node `vm.Script`로 모두 확인합니다. 초기 로컬 자산은 2026-10-21 조회·저장 신뢰성 개선 후 약 142KB였으며, 아래 운용 편의 개선을 포함한 회귀 한도는 155,000바이트입니다. 새 런타임 라이브러리나 초기 조회 요청은 추가하지 않습니다. GitHub Actions는 동일한 하네스를 실행합니다.


## 2026-10-21 운용 편의 개선

- 현재 기준월·업체/권역을 상단 고정 업무바와 Action Board 목록 위에 함께 표시합니다. 월·권역을 바꾸면 기존 세부 조건을 유지하면서 해당 범위로 갱신합니다. 목록 초기화와 검색어 해제는 선택한 월·권역을 바꾸지 않습니다.
- 전월 대비 카드는 실제 변화 영역으로 이동합니다. 신규 공급·공급 중단·X→O 개선 값은 해당 거래처 목록으로 연결합니다. 이전 월 자료가 없는 첫 자료 월은 변화값을 `—`로 표시하고 비교 불가를 안내합니다.
- 사업자번호는 하이픈 유무에 관계없이 검색할 수 있습니다. Excel에는 화면의 현재 범위·목록 조건·검색어와 일치하는 거래처가 저장됩니다.
- 고정 업무바에서 연동 현황, 조치 입력, 진행중·완료 영역으로 바로 이동합니다. 미전송은 거래처 수와 수정 항목 수를 구분하며, 고정 저장 버튼도 기존 명시 저장 동작을 사용합니다. 조회·검색·이동만으로 입력을 전송하지 않습니다.
- SRM 목록에 거래처명·사업자번호·권역 검색과 150처씩 더 보기를 추가합니다. 상태 카드의 전체 집계는 유지하며 검색 결과와 현재 표시 수를 별도로 보여 줍니다. 조치 이력이 많아도 마지막 거래처까지 확인할 수 있습니다.
- 로그인 전에는 대시보드의 키보드 조작과 접근성 탐색을 차단하고, 로그인 후 복원합니다. 조치 입력 필드에 거래처별 접근성 이름을 제공합니다.
- `tests/partner-usability-regression.mjs`는 실제 런타임의 선택 연동, 키보드 이동, 첫월 비교, 검색·Excel 일치, 명시 저장, 로그인 화면 전환을 검증합니다. `tests/srm-list-regression.mjs`는 150처 이후 탐색·상태별 검색·초기화·다른 범위로의 전환을 검증합니다. 운영 계정 로그인이나 운영 Google Sheet 쓰기는 테스트하지 않습니다.

### 월 공백과 조회 범위 검증

지속 X는 달력상 연속 월로 계산합니다. 예를 들어 6월과 8월이 X여도 7월 자료가 없으면 8월의 연속 기간은 1개월입니다. 12월→1월은 연속 월로 인정하며, 거래처 자료 누락이나 O 전환이 있으면 기간이 끊깁니다. `tests/calendar-streak-regression.mjs`에서 KPI·목록·위험도 계산의 일치를 검증합니다.

SRM 검색·상태·표시량은 파트너 로그아웃 또는 계정 전환 시 초기화합니다. 같은 계정에서 월·권역을 바꾸면 검색과 작성 중 협의 초안을 유지합니다.

최종 초기 정적 자산은 150,730바이트입니다. 변경 런타임의 캐시 버전은 `20261021usability1`이며, 추가 라이브러리나 초기 요청 없이 기존 로딩 방식을 유지합니다.
